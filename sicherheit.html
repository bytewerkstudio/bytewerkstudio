01 Wo es weh tut

Vier Türen. Die meisten Vorfälle kommen durch eine davon.

Sicherheit ist kein Produkt, das man einmal installiert. Sie ist eine Reihe von Entscheidungen an vier Stellen, an denen Daten, Code und Menschen aufeinandertreffen.

01

Fremder Code

Ein Kommentarfeld wird zum Script-Tag, ein Suchparameter landet im DOM. XSS braucht keinen kaputten Server — ein nicht escaptes Zeichen reicht.

  • Text als Text rendern, nie als HTML
  • CSP ohne unsafe-eval und CDNs
  • Allowlist für Links und Protokolle
02

Kontoübernahme

Passwörter werden wiederverwendet, Reset-Mails erraten, Sitzungen laufen nie ab. Der billigste Weg in ein System ist weiterhin ein gültiger Login.

  • PBKDF2-SHA256, 310.000 Runden
  • Sperre nach fünf Versuchen
  • Kurze Sitzungen, klares Abmelden
03

Datenabfluss

Eine Abfrage ohne Nutzerfilter, ein Export ohne Limit, ein Backup im öffentlichen Bucket. Daten verschwinden leise, nicht mit Alarm.

  • Row Level Security statt UI-Prüfung
  • Minimalrechte für jeden Schlüssel
  • Exporte mit Limit und Protokoll
04

Der Ausfall

Ein Zertifikat läuft ab, eine Platte füllt sich, ein Restore wurde nie getestet. Der Vorfall ist schlecht; ihn drei Tage später zu bemerken ist schlimmer.

  • Backups mit getestetem Restore
  • Uptime- und Zertifikats-Monitoring
  • Eine Seite: wer macht was

Content Security Policy

Nur diese Origin darf Skript ausführen.

Kein CDN, keine Inline-Handler, kein eval. Jede Quelle muss benannt werden. Ein blockierter Import fällt sichtbar in der Konsole aus — genau das ist der Zweck.

  • Gilt für: jede HTML-Seite
  • Kompromiss: Inline-Styles brauchen 'unsafe-inline'
  • Nächster Schritt: Nonce oder Hash im Build
sicherheit.html · <head>
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self';
               script-src 'self';
               object-src 'none';
               base-uri 'self';
               form-action 'self' mailto:;
               upgrade-insecure-requests">
Passwort-Speicherung

Absichtlich langsam. 310.000 Runden.

Ein schneller Hash ist ein Geschenk an jeden, der eine Tabelle stiehlt. PBKDF2 mit zufälligem Salt pro Konto macht jeden Versuch teuer — und die Kosten bleiben messbar.

  • Gilt für: Konten und Reset-Token
  • Passwort und Hash nie loggen
  • Sperre nach fünf Fehlversuchen

Row Level Security

Die Datenbank antwortet nur dem Eigentümer.

Ein versteckter Knopf ist keine Berechtigung. RLS legt die Regel in die Datenbank: Eine kopierte Anfrage mit fremder ID liefert nichts — egal, welcher Client sie geschickt hat.

  • Gilt für: jede Tabelle mit Nutzerdaten
  • Mit zwei Konten testen, nicht mit einem
  • Service-Role-Key bleibt auf dem Server
supabase/schema.sql · policies
alter table public.threads enable row level security;

create policy "threads_read_published"
  on public.threads for select
  using (published = true);

create policy "threads_insert_own"
  on public.threads for insert
  with check (auth.uid() = author_id);

create policy "threads_update_own"
  on public.threads for update
  using (auth.uid() = author_id)
  with check (auth.uid() = author_id);
Antwort-Header

Header sind der Teil, den man nicht wegklicken kann.

GitHub Pages liefert Dateien, setzt aber keine eigenen Header. Derselbe Block funktioniert auf Netlify und Cloudflare Pages; auf GitHub bleibt das Meta-Tag der Rückfall. Wir dokumentieren beides, statt es zu verschweigen.

  • Gilt für: den Hoster, nicht das HTML
  • HSTS erst, wenn HTTPS überall läuft
  • Prüfen mit: curl -I

06 Fragen

Was Kunden vor dem ersten Gespräch fragen.

Fehlt deine Frage, schreib zwei Sätze. Das reicht für eine erste Antwort.

Per E-Mail fragen
Ist eine kleine Website wirklich ein Ziel?
Angriffe laufen automatisiert. Gesucht werden bekannte Lücken, offene Formulare und wiederverwendete Passwörter — kein bestimmter Name. Kleine Seiten sind oft leichter erreichbar, weil niemand sie regelmäßig prüft.
Wie lange dauert ein Audit?
Für eine Website oder eine kleine Anwendung: fünf Arbeitstage. Danach ein Bericht mit Prioritäten und ein Gespräch von sechzig Minuten. Die Härtung dauert je nach Umfang weitere fünf bis zehn Tage.
Müssen wir Hoster oder Anbieter wechseln?
In der Regel nicht. Wir arbeiten mit dem vorhandenen Stack. Nur wenn der Hoster keine Sicherheits-Header erlaubt oder Backups fehlen, sagen wir das offen — und zeigen dann zwei konkrete Alternativen.
Was passiert bei einem akuten Vorfall?
Begleitungskunden erreichen uns innerhalb von 72 Stunden, bei einem aktiven Vorfall am selben Werktag. Erste Schritte sind immer dieselben: Zugänge sperren, Beweise sichern, Backups prüfen, dann erst wiederherstellen.
Bleibt der Code unser Eigentum?
Ja. Wir committen in dein Repository, dokumentieren jede Änderung und übergeben Schlüssel, Konfiguration und einen Wiederherstellungsplan. Es gibt keine Abhängigkeit von unserer Infrastruktur.
