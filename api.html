Quickstart

Drei Schritte zur ersten Antwort.

  1. Schlüssel holen

    Konto anlegen, Projekt öffnen, Schlüssel kopieren. Die Vorsilbe trennt die Umgebungen: bwk_test_ für die Sandbox, bwk_live_ für echte Daten.

  2. Anfrage senden

    Jeder Aufruf ist eine einfache HTTPS-Anfrage. Kein SDK nötig, kein Handshake, kein Token-Tausch.

  3. Antwort lesen

    Daten stehen in data, Blättern in meta, Fehler in error mit einem stabilen Code, auf den du verzweigen kannst.

Sandbox

Anfrage bauen, Antwort lesen.

Dieser Spielplatz läuft vollständig in deinem Browser gegen feste Testdaten. Nichts wird gesendet, kein Schlüssel gespeichert, keine Anfrage verlässt die Seite.

Geprüft wird nur die Vorsilbe: bwk_test_ oder bwk_live_. Alles andere wird ignoriert.

Ereignisse

Die API ruft zurück.

Fünf Ereignisse decken den Lizenz-Lebenszyklus ab. Jede Zustellung ist signiert, wird 24 Stunden mit wachsenden Abständen wiederholt und erscheint mit Antwortcode im Dashboard.

  • licence.createdEin Schlüssel wurde ausgestellt
  • licence.activatedErste Aktivierung auf einem Gerät
  • licence.revokedErstattung, Rückbuchung oder manuell
  • licence.expiredLaufzeit beendet
  • payment.failedAbo-Zahlung fehlgeschlagen
Zustellung prüfen 
import { createHmac, timingSafeEqual } from 'node:crypto';

// header: X-Bytewerk-Signature: t=1730000000,v1=8f2c…
export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(
    header.split(',').map((p) => p.split('='))
  );

  const expected = createHmac('sha256', secret)
    .update(`${parts.t}.${rawBody}`)
    .digest('hex');

  const a = Buffer.from(expected);
  const b = Buffer.from(parts.v1);
  return a.length === b.length && timingSafeEqual(a, b);
}

Vergleiche in konstanter Zeit und weise Zeitstempel älter als fünf Minuten ab — sonst lässt sich eine mitgeschnittene Anfrage erneut abspielen.

Sicherheit

Schlüssel, die nicht alles können.

Begrenzte Rechte, gehashte Ablage, getrennte Umgebungen. Ein verlorener Test-Schlüssel kostet nichts; ein verlorener Live-Schlüssel verliert nur das Recht, das du ihm gegeben hast.

Rechte je Schlüssel

Lesen, Schreiben, Webhook und Abrechnung sind getrennte Rechte. Ein Build-Server braucht nie Abrechnungsrechte.

Gehasht abgelegt

Schlüssel liegen als SHA-256-Hash mit erkennbarer Vorsilbe. Der Klartext wird einmalig angezeigt.

Test und Live getrennt

Getrennte Datenbestände, getrennte Limits. Ein Test-Schlüssel kommt an keine echte Lizenz.

Wechsel ohne Ausfall

Zwei Schlüssel dürfen gleichzeitig aktiv sein, damit du den neuen zuerst ausrollen kannst.

Keine Fremdskripte

Diese Seite lädt keine Analyse und kein CDN. three.js kommt von unserer eigenen Domain, abgesichert durch eine strikte CSP.

Fragen

Bevor du die erste Zeile schreibst.

Brauche ich ein Konto für die Sandbox?

Nein. Der Sandbox-Schlüssel entsteht lokal im Browser und funktioniert nur gegen die festen Testdaten. Für echte Daten braucht es ein Konto.

Was passiert über dem Kontingent?

Die API antwortet mit 429 und Retry-After. Nichts wird abgeschaltet und nichts still berechnet; nach Ablauf des Fensters laufen Anfragen weiter.

Kann ich monatlich kündigen?

Ja, jede Stufe läuft monatlich und endet zum Ende des Abrechnungszeitraums. Die jährliche Zahlung ist optional und entspricht zehn Monatsbeiträgen.

Wo liegen die Daten?

In der EU. Verarbeitung nach DSGVO mit AVV auf Anfrage, Löschung auf Anfrage, keine Weitergabe zu Werbezwecken.

Gibt es ein SDK?

Die API ist reines HTTP, jeder HTTP-Client funktioniert. Typisierte Helfer für TypeScript und Python sind in Vorbereitung; der Vertrag ändert sich dafür nicht.

Gibt es Selbstbetrieb?

Für Team-Kunden liefern wir den Lizenzdienst als Container-Image mit Compose-Datei. Der Support für den Betrieb ist Teil der Stufe.
