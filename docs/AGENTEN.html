In welcher Reihenfolge

21 Zweige einzeln zu mergen ist der teuerste Weg. Ein Integrationszweig, dann die Sonderfälle — so bleibt jeder Schritt prüfbar.

  1. Einen Integrationszweig wählen

    fable/qa-release oder integ/final als Basis nehmen — nicht beide. Sie enthalten bereits den Großteil der Seiten; alles andere wird darauf gelegt.

  2. Community einhängen

    fable/community bringt Forum, Entwickler-Abo, Sicherheits-Selbsttest und das 3D-Ideenregal mit. Konflikt in genau drei Dateien: components.js, sitemap.xml, README.md. Auflösung: ein Eintrag Community, forum.html bleibt als Seite erreichbar.

  3. Doppelte Foren entscheiden

    community.html (Forum + Abo + Sicherheit) und forum.html (nur Forum) decken dieselbe Aufgabe ab. Eines davon ins Menü, das andere per canonical auf das erste zeigen lassen — sonst konkurrieren zwei Seiten um dieselben Suchbegriffe.

  4. Prüfen, dann nach main

    1440 und 390 px ohne Überlauf, 0 Konsolenfehler, node --check für jedes geänderte Skript, Anker und Doppel-IDs. Erst danach auf main — GitHub Pages veröffentlicht direkt, es gibt keinen Rückweg über einen Build.
